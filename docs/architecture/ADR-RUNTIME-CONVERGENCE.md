# ADR: Runtime Convergence (Step 3)

**Status:** Accepted
**Date:** 2026-09-08
**Baseline Commit:** 85f4102a4802918b30387fd3848df6e0d92da026

## Context

The AEGIS NIDS project has evolved multiple entry points over time. This ADR documents the convergence to **ONE production runtime** per the Master Execution Roadmap (Step 3).

## Decision

**The single production runtime is `src/main.zig` built via `build.zig`.**

All other entry points are classified as:
- **Test-only** (`src/fuzz_entry.zig` → `src/tests/fuzz_main.zig`)
- **Control plane clients** (`tools/aegisctl.py`)
- **Installer** (`tools/installer.py` — CONSUMES build artifacts, not a runtime)
- **Operational tooling** (`scripts/*.bat`, `scripts/*.ps1`)

## Runtime Inventory

### 1. Production Runtime (ONE)

| Component | Entry Point | Build Target | Language | Purpose |
|-----------|-------------|--------------|----------|---------|
| **Core Daemon** | `src/main.zig` | `aegis_nids.exe` | Zig | Main NIDS daemon — wires all I01–II22 modules, runs named-pipe control server |

**Build:** `zig build` → `zig-out/bin/aegis_nids.exe`

**Dependencies (linked):**
- Rust PEP: `target/release/aegis_pep.dll`
- C Native Helpers: `build/Release/aegis_etw_helper.dll`, `aegis_fim_helper.dll`, `aegis_wfp_user.dll`
- Npcap SDK: `wpcap.lib`, `Packet.lib`

### 2. Test Runtimes (Optional, Non-Production)

| Component | Entry Point | Build Target | Language | Purpose |
|-----------|-------------|--------------|----------|---------|
| Fuzz Target | `src/tests/fuzz_main.zig` (via `src/fuzz_entry.zig`) | `aegis_fuzz.exe` | Zig | Fuzzing harness for decoder/parsers |

**Build:** `zig build fuzz` → `zig-out/bin/aegis_fuzz.exe`

### 3. Control Plane Client (Non-Runtime)

| Component | Entry Point | Language | Purpose |
|-----------|-------------|----------|---------|
| `aegisctl` | `tools/aegisctl.py` | Python | CLI operator — talks to daemon via named pipe `\\.\pipe\aegis_control` |

**Does NOT run the NIDS engine.** Connects to running daemon.

### 4. Installer (Non-Runtime)

| Component | Entry Point | Language | Purpose |
|-----------|-------------|----------|---------|
| Installer | `tools/installer.py` | Python | **CONSUMES** `build_manifest.json` + built artifacts → generates NSIS installer |

**Does NOT build the runtime.** Consumes artifacts from:
- `zig-out/bin/aegis_nids.exe`
- `target/release/aegis_pep.dll`
- `build/Release/*.dll`
- `go/aggregator/aegis-aggregator.exe`

### 5. Operational Tooling (Non-Runtime)

| Category | Examples | Purpose |
|----------|----------|---------|
| Service mgmt | `scripts/run_aegis.bat`, `scripts/stop_aegis.bat` | Start/stop Windows service |
| Build drivers | `scripts/build_drivers.bat`, `scripts/wdk_build_production.ps1` | WDK kernel driver build |
| Diagnostics | `scripts/diag_aegis_dirs.bat`, `scripts/diag_deep.bat` | Directory/health checks |
| Drivers install | `scripts/install_drivers.bat` | WFP/minifilter install |

**All are wrappers around the production runtime or build system.**

## Convergence Verification

### Build Contract (Step 4)

```bash
# All must succeed and produce compatible artifacts
zig build                    # → zig-out/bin/aegis_nids.exe
zig build test               # unit + integration
cargo build --release        # → target/release/aegis_pep.dll
cargo test --release         # PEP unit tests
cmake -B build -S .          # configure C native layer
cmake --build build --config Release  # → build/Release/*.dll
python -m pytest tests/      # control plane + integration tests
```

### Runtime Manifest (Step 5)

`runtime_manifest.json` declares:
- `runtime_version`
- `entrypoint`: `"src/main.zig"`
- `production_modules`: list of all modules wired in `main.zig`
- `init_order` / `shutdown_order`
- `golden_path`: sequence from capture → forensics

1. **Single build root:** `build.zig` is the only build entry point for production
2. **Single source root:** `src/main.zig` is the only production executable entry

5. **Single release root:** `build_manifest.json` (generated by `release_engineering.py`)
