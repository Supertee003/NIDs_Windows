# DIST-DLL-LOCK-001 - the relink lock was a stray process, not the product

## Symptom

`tests/release/test_native_build_and_scripts.py::test_bridge_builds_into_dist` failed for several sessions
with `LINK : fatal error LNK1104: cannot open file 'D:\NIDs_Windows\dist\aegis_ipc.dll'`, surviving
service stops and reboots of the daemon.

## What it was not

- Not an ACL problem: owner was `LAPTOP-PPN\User`, and `Authenticated Users` held Modify.
- Not a hardlink to the installed copy: both files had link count 1 and different file ids.
- Not the service: `Stop-Service AegisNids` did not release it.

Evidence that narrowed it: creating and deleting a new file in `dist/` worked, and the DLL could be
renamed but not appended to or deleted, which is the signature of an open handle that shares delete
but not write.

## What it was

An elevated module scan of every process found `pythonw` **PID 3168** mapping
`D:\NIDs_Windows\dist\aegis_ipc.dll` - a leftover process from an earlier automation run, not part of
AEGIS and not holding any service. `Stop-Process -Id 3168 -Force` released the file.

## Result

`python -m pytest -q tests/release/test_native_build_and_scripts.py` -> **10 passed**, including the
relink test. No project code changed for this; the defect was environment state and is recorded as such.
