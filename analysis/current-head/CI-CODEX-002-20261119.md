# Host-regression Phase T gate alignment — 2026-11-19

**Trigger:** after the BOM fix, `Host Regression (Phase T+K)` run `44381024125`
on `debd3c7` reached the tests and failed `test_aegisctl.py`: 5 failed, 42 passed,
3 skipped.

## Root cause

`.github/workflows/host-regression.yml` ran `tests/runtime/test_*.py` without the
conventions `ci.yml` already uses on Windows:

- four failures are `@pytest.mark.host_live` tests that require a running Windows
  control daemon (`incidents list`, `incidents top`, `iptest`, `rule search`).
  This Linux logic-layer runner has no daemon.
- `test_graph_builds_to_tmp` needs the optional `networkx` / `pyvis` packages;
  the workflow installed only `pytest`, while `ci.yml` installs both.

After that fix, run `44382186773` on `e560340` exposed one more Linux-only
failure: `test_go_vet_both_tag_variants` runs `go vet -tags service`, but the
service wrapper imports `golang.org/x/sys/windows/svc`, which cannot compile on
Ubuntu. The default-tag vet still runs everywhere; the service-tag vet is now
guarded by `sys.platform == "win32"` and remains a real check in Windows CI.

These are runner-environment failures, not a product regression: local
`python -m pytest test_aegisctl.py -q -m "not host_live"` gives **46 passed, 4
deselected**, and `tests/runtime/test_aggregator_entrypoints.py` gives **6
passed**.

## Patch

Records/CI-only change to `.github/workflows/host-regression.yml`:

1. `pip install pytest networkx pyvis` (matches `ci.yml`).
2. `python -m pytest "$f" ... -m "not host_live"` (matches `ci.yml`'s
   `not host_live` selection).

No product source, build input, signed candidate, installer, host state or
machine-map source commit changed. Build source remains
`f4cde3c503fd8b696183751a608b999768caa769`.
