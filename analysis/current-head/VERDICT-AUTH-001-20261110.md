## The hole (why this is a stop-the-line item)

#28 already shipped the versioned v3 frame (`a1024f2`) and moved the Go capture
path to evidence-only. Two things were still true:

1. **A producer could still author a verdict.** The wire carries `rule_id`,
   `severity` and `event_type`. `pushDecodedFrame` copied all three straight
   into `IpcEvent`, and two built-in detectors trusted them blindly:

   ```zig
   // src/detection/detection_engine.zig
   if (event.rule_id != 0 and event.event_type == .match_)      // -> suspicious, confidence 60
   if (event.event_type == .block)                              // -> critical, confidence 90
   switch (event.severity) { 1 => suspicious, 2 => malicious, 3 => critical }
   ```

   So a Go/WFP row that said "`TypeMatch`, rule 0xC0FFEE, severity 3" produced a
   verdict without any Zig detection having run. The Go classifier that used to
   do exactly that was dormant but still compiled, still tested, and one call
   site away from being live again — `nose/inject.go` was already sending
   `Severity: 1`, which `severityDetector` scores as *suspicious*.
2. **Nothing proved the invariant.** No test failed if a producer authored a
   verdict, in either language.

A code comment in `event_processor.zig` claimed "Zig is the sole verdict
authority", and that claim was true of the Aho-Corasick path but not of the
ingress path. That is the failure mode AGENTS.md calls a contradictory
source-of-truth document.

## Fix

### 1. Strip the claim at the one seam every producer passes (`event_queue.zig`)

`sanitizeAcquisitionClaim(ce)` returns the authority's view of the record:
`rule_id = 0`, `severity = 0`, and `.match_`/`.block`/`.ip_blocked` demoted to
`.forward` (the evidence carrier). Every other field — addresses, ports,
protocol, direction, payload, identity — is untouched, so no evidence is lost.
`pushDecodedFrame` applies it before the kind/severity mapping, then counts:

| Counter (`queue.stats.ingress_authority`) | Meaning |
|---|---|
| `claims_stripped` | frames carrying at least one acquisition-authored claim |
| `rule_id` / `severity` / `event_type` | per-field breakdown |

Why ingress and not the detectors: after this point `rule_id != 0` has exactly
one possible origin (Zig's AC/L4/L7 stage), so the detectors keep their simple
shape and become correct by construction. A detector-side check would need
provenance the `IpcEvent` does not carry by the time it runs.

Why demote rather than reject: a frame's bytes are still evidence. Rejecting it
would be a silent drop of observed traffic; demoting keeps the record and makes
the overreach visible in a counter.

### 2. Delete the Go second authority

| File | Change |
|---|---|
| `nose/signature_classifier.go` | **deleted** — `classifyNosePacket`, rule loading, rule-id hashing, severity ordinals |
| `nose/signature_classifier_test.go` | **deleted** |
| `nose/canonical_test.go` | the two classifier tests removed with it |
| `nose/inject.go` | `Severity: 1` → `0`; the fixture no longer claims a severity, it only carries addresses/ports |
| `nose/verdict_authority_test.go` | **new** — AST guard (below) |

The guard reads the package source rather than runtime behaviour, because the
regression it prevents is a *future* producer quietly reintroducing a verdict
that would be dormant in the shipped configuration:

- no non-test file except the two codec files (`canonical.go`,
  `golden_path_ffi.go`, which transport bytes verbatim) may assign
  `EventType` / `RuleID` / `Severity`;
- no `EventType: TypeMatch` literal anywhere outside them;
- `RuleID:` / `Severity:` literals must be exactly `0` — a variable or call is
  rejected rather than assumed harmless.

Negative control (guard proven to fire): setting `Severity: 2` in `inject.go`
produced

```
verdict_authority_test.go:92: inject.go:38:4 sets Severity to a nonzero value:
acquisition severity/rule ids are claims, not evidence
```

### 3. Existing test that encoded the old contract, corrected

`classifyForward names DNS by port` ended with `.match_ → signature_match`,
which is precisely the behaviour #28 forbids. It now asserts the demotion
(`.match_` on UDP/53 → `dns_query`), so the evidence identity survives and the
verdict does not.

## Invariant established

> After ingress, `rule_id != 0`, a nonzero severity, or a `.match_` kind can
> only come from a Zig detection stage. No acquisition tier can create,
> escalate, or launder a verdict by putting fields on the wire — and every
> attempt is counted in `queue.stats.ingress_authority`.

## Contract impact

None on the wire. No version bump, no vector change, no `struct_size` change:
v1/v2/v3 bytes and the six codecs are byte-identical. This is an admission
policy, documented in `shared/protocol/wire_v3.md` §"Ingress verdict strip".

## Authority / enforcement impact

Authority increases for Zig and decreases for everyone else: Go no longer has a
classifier at all, and WFP's header `rule_id`/`severity` can no longer reach a
verdict. `prevention_gate` stays `closed`; the strip removes the ability for a
producer to *claim* a block, it never creates one.

## Known consequence to watch on the next host window

`WFP` used to pass the driver header's `rule_id`/`severity` into the record.
Those are now stripped. If the driver populates them in observe mode, expect
`ingress_authority.claims_stripped > 0` from `capture_wfp` on the next deploy.
That is the counter doing its job, and it means the driver's attribution must be
re-homed into an evidence field in a separate slice — it must not be restored to
the verdict channel.
