## 1. Result

The alert surface returned:

```json
{
  "action": "Alert",
  "event_id": 0,
  "name": "Registry Run key modified (HKCU)",
  "payload_len": 94,
  "record_seq": 114434,
  "rule_id": "REG-HKCU-RUN",
  "rule_num": 3,
  "severity": "High",
  "source": "registry_sensor",
  "verified": true
}
```

The daemon log named the actual hive and SID:

```
registry change matched rule 3:
HKU\S-1-5-21-2240144573-294256931-834073773-1001\Software\Microsoft\Windows\CurrentVersion\Run
```

So the chain is complete:

```
user hive change -> HKU\<SID>\...\Run watcher -> rule 3 (match path HKCU\...\Run)
-> forensic record with the HKU path (payload_len 94) -> named alert REG-HKCU-RUN
```

`payload_len=0` from the earlier canary is gone: the record now carries the key
path.

## 2. What changed to make this pass

- `RegistryMonitor` enumerates `HKEY_USERS` and opens
  `<SID>\Software\...\Run` for every loaded hive; the event path keeps the SID,
  the match path is normalized to `HKCU\...\Run`.
- rule 3 is registered in `registryThread`.
- `registryThread` pushes `reg_ev.path` as the payload.
- the CLI maps ids 1/2/3 to named alerts (ALERT-MAP-001).
- `aegisctl alerts` now anchors its scan near the newest ring record instead
  of replaying the oldest page (ALERT-SCAN-001).

## 3. Tooling note (ALERT-SCAN-001)

The first attempts returned only R1004 file alerts because `forensics.list`
pages oldest-first and `alerts` capped at 5 pages / `want` alerts. The scan now
reads `ring_records`/`oldest_record_seq`, starts 4,096 records before the tip,
and pages up to 25 times. The E5 canary needed `--limit 1000` because R1004
noise fills the early result set; the registry alert was found at seq 114434
with `payload_len=94`.

A `--rule` filter is still the right ergonomic fix (it would stop scanning once
the requested rule is found); it is not in this patch.

## 4. Limitations

- One host, one loaded user hive, one canary.
- Hives loaded **after** the registry thread starts are not watched until a
  restart; boot-time logon needs a re-scan (or the ETW lane).
- RegNotify does not report the value name; rule 3 means "something under the
  user's Run key changed".
- Forensic retention is still ~16k records; query promptly or use the anchored
  scan.
- ETW registry paths are still not normalized into the HKCU rule; the native
  watcher is the authority.
