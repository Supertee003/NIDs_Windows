# GAP-STATUS-001 — 227 known gaps that could not say whether they were open

**Created:** 2026-11-14
**Build source:** unaffected; `EVIDENCE_INDEX.json` + `tests/` only.
**Level:** E2 (schema guard), with **no reassessment** of any gap's substance.

---

## 1. The state before

`EVIDENCE_INDEX.known_gaps` held 276 entries. Counting them by `status` gave:

```
None (field absent)      227
CLOSED                    41
OPEN                       4
CLOSED_BY_EVT-008          1
PASS                       1
E5_VERIFIED_TOTAL_LOSS_OPEN 1
```

So the number a release decision actually needs — *how many gaps are open* — could
not be read off the index at all. Four different spellings existed for statuses
that were not statuses (a test name, an event id, a verdict), and 227 entries
simply had no verdict.

## 2. What was done — classification, not reassessment

* the 227 entries with no `status` became **`UNRECORDED`**;
* `CLOSED_BY_EVT-008` → `CLOSED` (it says it is closed);
* `PASS` → `UNRECORDED` (a verdict, not a closure statement about a gap);
* `E5_VERIFIED_TOTAL_LOSS_OPEN` → `OPEN` (its own name says open);
* `known_gaps_status_note` added at the top of the index, stating that
  `UNRECORDED` means *not re-verified* and **never** means closed;
* `GAP-QLOSS-ISOLATION-002` gained a `next_step` and a `current_observation`
  (2.5 h soak: dropped 0, shed 0, budget 3500) — an observation, not a closure.

Result: `{'UNRECORDED': 228, 'CLOSED': 42, 'OPEN': 6}`.

The 6 open gaps are now the honest worklist: `DEFECT-READY-001`,
`DETECT-L4-001`, `CAPTURE-LOOPBACK-001`, `L7-NO-JOIN-001`, `BUILD-NETINT-001`,
`GAP-QLOSS-ISOLATION-002`.

## 3. The guard

`tests/release/test_known_gap_status.py` (4 tests):

1. every gap's status is one of `OPEN`, `CLOSED`, `UNRECORDED`;
2. ids are unique and non-empty;
3. every `OPEN` gap carries `blocked_by`, `next_step` or `fix` — an open gap with
   no next step is a note, not a tracked item;
4. the index explains what `UNRECORDED` means and says it is not a closure.

```
$ python -m pytest -q tests/release/test_known_gap_status.py tests/release/test_evidence_index_valid.py
7 passed
```

## 4. What this does not claim

1. **No gap was closed.** `UNRECORDED` is the opposite of a claim: it says the
   status was never recorded and has not been re-verified.
2. **228 entries remain unassessed.** Triaging them is real work — reading each
   description and checking the current tree — and was not attempted here.
3. **The count is a snapshot** of an index maintained by hand; the guard keeps it
   well-formed, not correct.
4. **`UNRECORDED` may hide open defects.** The 6-open figure is a floor, and the
   report says so rather than presenting it as the true backlog.
