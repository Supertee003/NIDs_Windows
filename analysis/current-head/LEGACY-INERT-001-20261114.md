# LEGACY-INERT-001 — a quarantine directory whose files still ran

**Created:** 2026-11-14
**Build source:** unchanged (`87e780e`); this patch touches `tools/legacy/` and
`tests/`, no runtime path
**Level:** E2 (61 pins: 28 parametrised parse checks, 28 guard checks, plus
behavioural, compile and reachability checks)

---

## 1. What was wrong

`tools/legacy/` is the project's quarantine: the pre-unification dashboard, the
retired `aegisctl` command modules, the orphan Rust shield crate and eleven
one-shot patchers. The earlier health audit recorded the directory as "may not
be part of the production runtime" — but nothing enforced that, and two facts
made the claim false in practice:

1. **The files still ran.** `patch_graph_daemon.py` rewrites
   `scripts/aegis_graph.py`, `fix_console.py` and `fix_console2.py` rewrite
   `tools/aegisctl/commands/console.py`, `update_auth.py` rewrites
   `AUTHORITY_MAP.json`, `update_console.py` rewrites the console again. A glob
   over `tools/`, a fatigue-driven `python tools/legacy/...`, or a future
   "cleanup script" would have mutated tracked files — `AUTHORITY_MAP.json` is a
   truth artifact, so that is a truth mutation, not a stale comment.
2. **One of them did not parse.** `fix_console.py:95` ended a `new_running`
   triple-quoted block with `""""`, an unterminated f-string. The 2026-09-27
   audit called it out: "a repository-wide compile gate cannot pass until it is
   fixed, excluded explicitly, or removed". It had been left as debt for two
   months, which is why `compileall tools/` was not a check anyone could run.

## 2. What changed

- `fix_console.py:95` now closes the f-string and the outer block properly; the
  file parses.
- All 28 tracked Python files under `tools/legacy/` carry a quarantine header and
  a guard placed **after** any module docstring and `from __future__` import, so
  the file is still valid Python but exits before any line of its original body:

  ```python
  raise SystemExit(
      "QUARANTINED: tools/legacy/<name>.py must not run; retained for history only."
  )
  ```
- The bodies are otherwise untouched: this is a guard, not a rewrite, so the
  history the directory exists for is still readable.

## 3. Verification

`tests/security/test_legacy_quarantine.py`, 61 passed:

| Pin | What it refuses |
|---|---|
| census | a new file under `tools/legacy/` that has not been classified (and an allowlist entry pointing at a file that is gone) |
| per-file `ast.parse` | reintroducing the `fix_console.py:95` class of error |
| per-file guard check | a file whose first statement is not the quarantine guard, a guard that does not name its own path |
| `update_auth.py` run for real | exit 0, or `AUTHORITY_MAP.json` changing (sha256 before/after) |
| `compileall tools/legacy` | any file in the tree that does not compile |
| reachability | any product file (`.py/.ps1/.zig/.go/.rs/.ts/.c/.nsi`) naming `tools/legacy` |
| orphan crate | a `[workspace]` in the root `Cargo.toml`, or a build file naming the crate |

Mutation control: deleting the guard from `update_auth.py` fails 2 pins
(`test_every_legacy_python_file_refuses_to_run[...update_auth]` and
`test_running_a_legacy_patcher_writes_nothing`); restoring it returns 61 passed.

`python -m compileall -q tools/legacy` exits 0 at this HEAD (it exited 1 before).

## 4. Limitations

1. **E2.** No runtime behaviour changed, so there is nothing to verify at E5.
2. **The guard is a runtime refusal, not a removal.** A reader can still copy a
   body out of a legacy file; the point is that no path can *execute* it where it
   sits. Deleting the directory is an owner decision (it is the record of what
   was replaced).
3. **The Rust orphan is inert by absence, not by proof.** The pins show it is not
   a workspace member and no build file names it; they do not prove no developer
   builds it by hand.
4. **`tools/legacy/Dashboard.py.before-unified-snapshot` is data.** It has no
   `.py` suffix, so it never executes; the census allowlists it with that reason
   rather than pretending it is guarded.
