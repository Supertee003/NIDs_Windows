# LAB-WIFI-001 — the sensor was watching a network the lab never used

**Created:** 2026-11-15
**Commit:** `a862985` (tools/tests/docs only — nothing in `RUNTIME_PATHS`, so the
`SOAK2-20261115` window stays valid)
**Level:** E1 finding on the live host, E2 pins for the new tool, and one real
read-only host measurement (`--preflight`).

---

## 1. The finding

The operator set up the intended lab: this Windows host is the victim, a Kali VM
is the attacker. Before firing anything I asked the only question that can turn a
correct attack into a silent zero: *which interface does the sensor actually
read?*

It reads Wi-Fi, not the VM lab network.

```
$ python tools\lab_attack_window.py --preflight
capture device : \Device\NPF_{5FD31C6E-DE48-44CB-838E-14667A04DA4B}
  description  : Killer(R) Wi-Fi 6 AX1650i 160MHz Wireless Network Adapter (201NGW)
  target IPv4  : 192.168.1.39
preflight      : wire ingress advancing (+5219 frames)
PREFLIGHT OK: the sensor is receiving frames on this device
```

Three independent facts agree:

| Fact | Value | What it proves |
|---|---|---|
| `nose/capture.go:firstUpDevice` | skips `wan miniport`, `hyper-v`, `vmware`, `bluetooth`, `wi-fi direct`, `teamviewer`, `loopback`; takes the first remaining adapter **with an address** | the selector is *designed* to refuse VMnet |
| `status.packets_captured` vs `Get-NetAdapterStatistics` | +5754 sensor frames vs +5093 Wi-Fi `ReceivedPackets` in the same 11 s | the counter tracks the Wi-Fi NIC, not an idle virtual one |
| `queue.stats.by_source` | ordinal `1` `capture_npcap` pushed 1,169,815, dropped 0 | the canonical ingress is the live network path |

So a Kali VM on host-only VMnet1 attacking `192.168.126.1` produces packets that
are entirely real and entirely invisible. The detector is not at fault, and
"0 detections" from that topology is not a detection failure — it is a capture
topology fact.

There is a second consequence, and it is the one that matters for the release:
`RB-021` (the host-only proof) requires the machine `AEGIS_DAEMON_IFACE` pin plus
a **service restart**. A restart inside `SOAK2-20261115` ends the window
(`analysis/current-head/SOAK2-20261115.md`). The only honest laboratory left while
the window runs is the one that attacks the link the sensor already owns.

## 2. The detection chain on that link, checked rather than assumed

A lab that fires at Wi-Fi is only meaningful if the captured frames reach the
detectors. Each hop was read at current HEAD:

| Hop | Evidence |
|---|---|
| Nose attaches bytes | `nose/capture.go:captureAttachment` builds a v3 envelope with the bounded frame, `EventV3MaxPayload = 1024` |
| Nose attaches flags | `ContextFlags` transport lane (DEPLOY-131), read back by `canonical.getTcpFlags` |
| Zig attributes it to the sensor it came from | `event_queue.zig:480` `ev.source = legacySourceFor(.npcap_sensor)` → `.capture_npcap` |
| Payload rules run | `event_processor.zig:280` Aho-Corasick over `qe.payload` for every source except `capture_host_net` |
| L4 rules run | `event_processor.zig:307` gated on `ev.source == .capture_npcap` — satisfied by the line above |
| Rate/window semantics | `l4_matcher.zig` `distinct_dst_ports` (R9006, 20/10 s) and `count` (R9002, 50/1 s) |

Two consequences worth stating plainly:

* `nmap -sS` of ≥ 20 ports from Kali reaches **R9006**, and a ≥ 50 pps ICMP burst
  reaches **R9002**, over Wi-Fi, today, with no restart.
* L7 rules need a completed connection and payload bytes; a SYN-only scan
  exercises L4 only. That is protocol reality, not a gap.

## 3. What was added

**`tools/lab_attack_window.py`** — two modes, both read-only:

* `--preflight` runs the shipped selector over `aegis-nose.exe --list-devices`,
  reports the device, its description, and the IPv4 the attacker must target,
  then samples ingress for 5 s. Exit `3` means "the sensor is not on that
  segment — do not fire": the failure this record exists to prevent.
* window mode takes a byte offset into the durable evidence log plus a runtime
  snapshot, waits while the operator attacks, then reports **only** what changed:
  frames gained, rows appended in that interval, rows attributed to
  `--expect-src`, per-rule counts resolved against `configs/Rules.json`, and the
  queue cost (`dropped`, `shed`, `source_quota_shed`).

Verdicts are fail-closed on purpose:

| Verdict | Exit | Condition |
|---|---:|---|
| `PASS` | 0 | ingress advanced **and** ≥1 appended row names the attacker |
| `NO_ATTRIBUTION` | 2 | ingress advanced, nothing names the attacker |
| `BLIND` | 3 | ingress did not advance, or the counter went backwards (restart) |
| `INVARIANT` | 5 | any row claims a host effect, or a non-`observed` enforcement status |

`PASS` deliberately requires two independent facts. Either one alone is not a
detection proof: a moving counter with no attributed row is ambient noise, and an
attributed row without a moving counter is a replay or a stale log.

**`docs/runbooks/RB-022-wifi-bridged-lab.md`** — the procedure: prove the path,
bridge Kali, verify reachability, fire above threshold, read the verdict. It
states the trade-off against `RB-021` rather than implying both are available at
once.

## 4. Pins

`tests/tools/test_lab_attack_window.py` — 20 tests, no host touch:

| Pin | Prevents |
|---|---|
| selector skips VMware/Hyper-V/Bluetooth and picks the physical NIC | the tool blessing a segment the NIDS cannot see |
| selector never reports VMnet as the watched device when a physical NIC exists | the exact misreading in §1 |
| selector falls back to the first addressed device | a host with only virtual links reporting "no device" instead of the truth |
| `usable_ipv4` drops `fe80::`, `169.254.*`, `127.*` | advertising an unattackable target |
| log delta returns only appended **complete** lines, offset stops at the last newline | a half-written object counted as evidence, or a row skipped forever |
| rotation (shorter log) does not replay old rows | stale offset over a rotated file |
| `fnv1a32` matches the Zig golden table (`R1001` → `3813986375`) | every attributed row labelled with the wrong rule |
| verdict matrix: PASS / NO_ATTRIBUTION / BLIND / backwards counter / INVARIANT | a green result from one fact instead of two |
| markdown renders device, target, deltas and verdict | an artifact that cannot be audited |

## 5. Limitations, stated

1. **The tool measures; it does not decide that detection works.** `PASS` means
   frames arrived and a row named the attacker. Which rule fired, and whether its
   bytes were on the wire, still has to be read by a human against the capture.
2. **Promiscuous mode is off** (`pcap.OpenLive(..., false, ...)`). On Wi-Fi the
   sensor sees frames addressed to this host and broadcast, not other stations'
   traffic. Attacks on the host work; a Kali scan of a third party does not.
3. **Wi-Fi client isolation** breaks the topology at the AP, before the NIC. The
   runbook makes ping the gate for exactly that reason.
4. **Booting a VM is real load.** The tool never restarts a service, so it cannot
   invalidate a soak window by itself — but a Kali boot plus a flood can still
   burn the drop budget. `SOAK2` has 2,113 drops of headroom left.
5. **One stale comment found and deliberately not fixed**:
   `event_processor.zig:335` says direct Npcap is "the only ingress with a full
   Ethernet payload". Since wire v3 the Go Nose path carries 1,024 bytes, so the
   claim is no longer true — the *code* is right, the comment is not. A `src/`
   edit is a runtime commit and would reopen the soak, so it is queued for the
   post-soak patch set (see `GAP-TRIAGE-20261116.md`).
