## Two defects found while producing this candidate

Both were found by checking the artifact instead of trusting the tool's
`RC PASS`.

### 1. The signature did not survive a clone (`SIGNED-TREE-001`)

`.gitattributes` pins `* text eol=lf`, so git rewrote the CRLF bytes that had
been signed:

```
ad7948c  signed C150224584...  committed 0A86680FE5...
f5cc38e  signed 358FD0A37A...  committed 16D9D3C1A5...
```

`tools/sign_release.py --verify` passes on the signing machine and would fail on
every fresh clone — the one place a release signature has to work. Fixed by
`release/** -text` in `.gitattributes`, re-staging each signed tree
byte-for-byte, and `tests/release/test_signed_tree_bytes.py`, which recomputes
every committed `SHA256SUMS` digest and pins the attribute.

### 2. A signed tree shipped a pytest cache (`PACKAGING-CACHE-001`)

The first candidate (now deleted) copied `brain/aegis_brain_cython/.pytest_cache/`
into the release tree: `nodeids` changes on every test run, so the signed bytes
were unreproducible and the artifact recorded which local tests had run.
`tools/release_candidate.py` now ignores pytest/mypy/ruff/hypothesis caches and
shell residue (`COPY_IGNORE`), pinned by
`tests/release/test_release_candidate_packaging.py`.

## Soak window handling

The abandoned window `admin-evidence/e5-clean-host-20261117-soak3` was never a
24 h soak: baseline 19:21, last delta 20:37 → 1.28 h, measuring a runtime that
no longer exists. Its two `soak-*.json` files were renamed to
`abandoned-soak-*.json` (bytes unchanged) with `ABANDONED.md` beside them, so
the gate reads the honest newest artifact — `e5-clean-host-20261115-soak2`
(48.43 h, FAIL: daemon restarted mid-soak) — instead of a half-open window.

The owner runs the final 24 h window last, against the installed `6.0.0`
bundle. `tools/host_soak_check.py` writes a fresh `soak-*.json` in a new window
directory; that becomes the newest artifact the gate reads.
