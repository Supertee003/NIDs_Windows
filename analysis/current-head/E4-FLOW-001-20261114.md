# E4-FLOW-001 — the first system-integration gate, and the defect it found immediately

**Created:** 2026-11-14
**Build source:** `tests/integration/` only — no `RUNTIME_PATHS` entry, so the
running 24 h window is unaffected.
**Level:** E4 (system integration against the live product) for the flow checks,
plus one **open defect** recorded with `xfail(strict=True)`.

---

## 1. Why this gate exists

`EVIDENCE_INDEX.json` counts `E4_count: 0` and `E6_count: 0`. Everything proven
so far was unit, component or single-host-preflight level. No check anywhere
asserted the claim a NIDS lives on: *a real packet on a real interface reaches the
forensic ring and comes back out through the operator CLI.*

`tests/integration/test_e4_live_pipeline.py` does that, through the product's own
CLI (`tools/aegisctl.py`), against the installed daemon:

| Check | Assertion |
|---|---|
| `forensics verify` | `verified: true`, `integrity: ok`, `records > 0` |
| `forensics list` | every record `verified`, `source_space: canonical`, has a `source_name` |
| real loopback traffic | 4 TCP connects on 127.0.0.1, then `Packets captured` and `ring records` are non-zero and do not go backwards |
| `queue` | `dropped=0` and `shed_overload=0` |
| cross-surface health | status / health / readiness must agree on degraded-ness |

It skips (visibly) when no daemon answers, so CI without the product reports a
skip instead of a false pass.

## 3. DEFECT-READY-001 — open, found by this gate

```
health --json : state DEGRADED, degraded true,
                subsystems all RUNNING (7/7),
                workers.failed false, failure_reasons []
readiness     : degraded true, degraded_components [],
                failure_reasons ["degraded_without_named_component", "state_degraded"],
                overall_gate false
```

The daemon is degraded and cannot say what is degraded. Every named surface is
healthy: seven subsystems RUNNING, workers `failure_reasons: []`, queue `dropped=0`,
`loss_budget` intact, PEP READY. `readiness` therefore reports *not ready* for a
system with no identifiable problem — the exact condition `AGENTS.md` lists as
STOP-THE-LINE ("degraded without named component") and the contradictory
source-of-truth class it forbids.

This is recorded, not worked around:

* the check is `xfail(strict=True)` with the defect id in its reason, so it is
  **not counted as a pass** and a fix turns the suite red until the marker is
  removed;
* the gap is added to `EVIDENCE_INDEX.known_gaps` as `DEFECT-READY-001`.

It is also **not fixable in this window**: the fix is in `src/`, and any commit
touching `src` after 2026-11-14T22:20:15 invalidates the running soak.

## 4. Limitations

1. **E4 means "the flow moves on this host", not "the flow is correct".** No
   attack traffic was injected; detection quality is untouched by this gate.
2. **Loopback traffic is a weak stimulus.** It proves capture → pipeline → ring →
   CLI, not that an external interface or a noisy link behaves the same.
3. **`xfail` is bookkeeping, not proof.** The health inconsistency remains until
   someone fixes `src/`.
4. **The gate depends on a running daemon.** Without the product installed the
   run reports skip, which is honest but means a CI runner proves nothing.
