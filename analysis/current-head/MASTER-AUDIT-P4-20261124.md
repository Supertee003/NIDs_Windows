## 8. F6 — detector errors silently swallowed by `catch null` · ตรวจพบ · DEFERRED (dedicated slice)

- **Path:** `src/pipeline/event_processor.zig:452,474,489`; error-propagating callees `src/detection/correlator.zig:83`, `src/detection/anomaly_detector.zig:89`, `src/detection/threat_tracker.zig:137`; outer catch `src/pipeline/event_processor.zig:1258-1263`.
- **Current text:** `if (corr.observe(ev) catch null) |corr_rule_id| {` (and `ad.observe`, `tt.observeFlowThreat`). The callees use `try ...getOrPut(...)`; the only processing-error counter is at the outer `processEvent` catch.
- **Reason:** an allocation failure in correlation, anomaly or threat tracking is discarded without moving a counter. The event continues, so this is silent **detection degradation** (not proof of silent event loss). It is inconsistent with the health contract's error accounting.

- **Why deferred:** this is a behavior/observability change on the source tree, requiring a full rebuild and a real test; it must not be smuggled into a records patch.

## 9. F7 — two different `data_loss_observed` semantics · ตรวจพบ · DEFERRED (design decision)

- **Path:** `src/control/state_machine.zig:287-289,429-436`; `src/daemon.zig:227-243`; `src/pipeline/runtime_state.zig:24`.
- **Current text:** lifecycle comment says the booleans are "the same booleans the health contract publishes"; daemon sample uses `.data_loss_observed = dropped > last_dropped,` (fresh); state machine uses `queue_drops > loss_budget` (cumulative, default budget 0).
- **Reason:** after one drop, the 5 s lifecycle sample can return to RUNNING while health stays DEGRADED until restart. The same payload can carry `state: DEGRADED` with `runtime_state: RUNNING`. Source proves the semantics differ; the comment claiming they are the same is wrong.
- **Replacement applied (records-only part):** the control API comment and CLI message now name the two semantics and both disagreement directions; `health_state_disagrees` was added to the control payload.
- **Remaining replacement direction:** choose one loss semantics in the Zig daemon, or rename the lifecycle input `fresh_loss_observed` and update the contract/API/maps.
- **Acceptance criteria:** a single drop produces a documented, stable pairing across both surfaces; the comment no longer claims identical booleans.
