# TOOLS-IMPORT-001 — two files under `tools/` did work when they were imported

**Created:** 2026-11-14
**Build source:** unchanged (`87e780e`); this patch touches `tools/` and `tests/`
**Level:** E2 (82 pins: an import probe per module plus a static module-scope
write check)

---

## 1. What was wrong

AGENTS.md TEST HYGIENE rule 1 says product modules under `tools/` must be
importable with no socket bind, no serve loop, no banner on stdout and no
`sys.exit`. Nothing checked it, and two files broke it:

| File | What importing it did |
|---|---|
| `tools/update_health_cmd.py` | read `tools/aegisctl.py`, replaced its `cmd_health` and **wrote the file back**, then printed `Done` |
| `tools/create_manifest.py` | read `src/main.zig`, built a 300-line manifest and **wrote `runtime_manifest.json`** (a truth artifact) |
| `tools/probe_control_pipe.py` | dialled the live control pipe and printed JSON stage lines |

Any tool that walks `tools/` — an inventory builder, a doc generator,
`python -m doctest`, `compileall`, an import-hygiene probe — triggered all
three. The first two are tree mutations; the third is a host effect on the
daemon's IPC endpoint.

`update_health_cmd.py` was also **stale**: `getRuntimeHealth`, the symbol its
replacement body imports, does not appear in `aegisctl.py` at all, so the guard
`if old_func in content` would have printed `Old cmd_health not found` and then
written the file back unchanged. It could only mutate the tree, never help.

## 2. What changed

- `tools/update_health_cmd.py` → `tools/legacy/update_health_cmd.py`, with the
  LEGACY-INERT-001 quarantine guard (it is history; the patch it applies was
  never applicable).
- `tools/create_manifest.py`: the whole body moved into `main()`, with a
  `__main__` guard. Verified behaviour-preserving: two consecutive runs produce
  byte-identical manifests apart from the `date` field, and the wrapping changed
  no output key.
- `tools/probe_control_pipe.py`: the pipe dial moved into `main()`; the module
  now imports without touching the pipe and keeps every printed stage line when
  run as a script.
- `tests/security/test_tools_import_hygiene.py`: every tracked `.py` under
  `tools/` (excluding `tools/legacy/`, which raises `SystemExit` by design) is
  imported in a subprocess — package modules by dotted name so relative imports
  resolve as the CLI resolves them — and must exit 0 with **empty stdout and
  stderr**. A second pin parses each file and refuses a module-scope
  `write_text` / open-for-write / `json.dump`, so a new patcher fails even if the
  probe is skipped.

| Check | Result |
|---|---|
| `pytest -q tests/security/test_tools_import_hygiene.py` | 82 passed, with `-W error::SyntaxWarning` |
| import probe, all 20 `tools/**.py` modules | exit 0, 0 bytes stdout, 0 bytes stderr |
| `python tools/create_manifest.py` | exit 0; output identical to the pre-patch output except `date` |

## 4. Limitations

1. **E2.** Nothing about the running stack changed; this is import hygiene.
2. **The probe runs each module once, in-process, on this host.** A module whose
   side effect needs a specific environment (a missing driver, a stopped
   service) could pass here and still misbehave elsewhere.
3. **`tools/legacy/` is exempt by construction.** Its files raise at import —
   that is the quarantine contract from LEGACY-INERT-001, not an import effect.
4. **The static check is syntactic.** It looks for module-scope writes through
   `write_text`, `open`, and `json.dump`; an obfuscated write (`os.system`,
   `shutil.copy`) would still pass the static pin, though not the runtime probe.
