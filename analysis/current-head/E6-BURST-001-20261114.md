# E6-BURST-001 — attack-shaped traffic in front of the live pipeline for the first time

**Created:** 2026-11-14
**Build source:** `tests/integration/` only — no `RUNTIME_PATHS` entry, soak unaffected.
**Level:** E6 (production simulation) for the burst path; the stimulus is a
localhost port scan, not a captured attack pcap.

---

## 1. Why

`EVIDENCE_INDEX` counted `E6_count: 0`. No gate had ever put attack-shaped
traffic in front of the running pipeline, so "AEGIS sees an attack" and "AEGIS
does not act on an attack" were both unasserted claims.

`tests/integration/test_e6_attack_burst.py` opens 150 TCP connections across
localhost ports — a port scan of the host itself. Nothing leaves the machine and
no remote address is touched, which is what makes it safe to run on a working
system.

## 2. Measured behaviour

Stimulus: 150 connects, 5 s settle, metrics read through `aegisctl.py metrics`
before and after. Observed delta on the live host:

| Counter | Delta |
|---|---|
| `detections` | +1 |
| `anomalies` | **+52** |
| `forensic_records` | **+4299** |
| `packets_captured` | **+3171** |
| `blocks` | **0** |
| `confirmed_blocks` | **0** |
| `confirmed_quarantines` | **0** |

So the burst is captured, scored and stored — and the enforcement counters stay
at zero. `health --json` reports `rust_pep.host_effect_capable: false`.

## 3. What the gate asserts

1. `forensic_records` grows — the burst became evidence;
2. `packets_captured` grows — it was the sensor that saw it;
3. `anomalies` grows — it was scored, not merely stored;
4. `blocks`, `confirmed_blocks`, `confirmed_quarantines` remain **0** and the PEP
   reports `host_effect_capable: false` — the detection-only invariant.

Point 4 is the safety invariant: it fails loudly if the product ever begins to
enforce.

## 4. Verification

```
$ python -m pytest -q tests/integration/test_e6_attack_burst.py
2 passed in 30.46s
```

## 5. Limitations — read these before quoting the gate

1. **A localhost port scan is not a real attack.** It exercises the burst and
   scoring path; it does not prove detection of malware, exploit traffic, C2 or
   lateral movement.
2. **`detections` moved by 1** — the +52 `anomalies` is the robust signal. One
   detection out of a 150-port scan is *weak*, and whether that is correct
   depends on the ruleset (`rules_loaded: 23`), which this gate does not judge.
3. **No detection-quality measurement**: no false-positive rate, no ground truth,
   no comparison against a known-labelled pcap (the repository ships none).
4. **One host, one build, one protocol family.** Nothing here says anything about
   IPv6, UDP, TLS-encrypted C2 or a second machine.
5. **`policy_ir.loaded: false`** was observed in `metrics` and first written up
   here as a possible contradiction with `policies_loaded: 6`. It is not one.
   `metrics.policy_ir` reflects `g_policy_ir` (`src/control/handler_registry.zig:2175`),
   which is populated only from the optional TS-authored mirror
   `configs/policy_ir.json` — a file absent from the repository and from the
   bundle, and whose absence `src/daemon.zig` documents as normal. The six
   policies come from `configs/policies.json` into the runtime `PolicySet`.
   Different objects, both reporting truthfully. Corrected here rather than left
   as a scare.
