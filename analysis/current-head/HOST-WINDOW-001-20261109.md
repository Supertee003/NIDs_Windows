# HOST-WINDOW-001 — one elevated window, D1 to D5

**Created:** 2026-11-09
**Closes:** R-05, R-06, R-07, R-08 (and the host half of R-01)
**Cannot close:** R-09 (key custody) — that is an ownership decision, not a window
**Runs on:** the enrolled Windows host, elevated, with physical or RDP access to
recover if networking drops

The point of this document is that the window is executed once, in order, with
a transcript per step. Every step has a pass criterion and an abort condition;
none of them is decided by impression.

---

## 0. Preflight (10 minutes, before anything changes)

```powershell
# 0.1 Free space and current state
Get-PSDrive D | Select-Object Used,Free
Get-Service AegisNids,AegisAggregator,AegisWfp,AegisMinifilter | Format-Table -AutoSize
Get-Process aegis_nids,aegis-aggregator-service,aegis-nose -ErrorAction SilentlyContinue

# 0.2 Record the installed binaries before touching them
$stamp = Get-Date -Format yyyyMMdd-HHmmss
$backup = "D:\NIDs_Windows\admin-evidence\host-window-$stamp\rollback"
New-Item -ItemType Directory -Force -Path $backup | Out-Null
Copy-Item "C:\Program Files\AEGIS NIDS\runtime\*" $backup -Recurse -Force
Get-ChildItem $backup -File | ForEach-Object {
    "{0}  {1}" -f (Get-FileHash $_.FullName -Algorithm SHA256).Hash, $_.Name
} | Tee-Object -FilePath "$backup\SHA256SUMS.txt"

# 0.3 The tree must be frozen: the candidate is a commit, not a working copy
git -C D:\NIDs_Windows status --porcelain
git -C D:\NIDs_Windows rev-parse HEAD
```

**Pass:** services listed, backup completed with a hash list, worktree clean.
**Abort:** any service already crashed, or the worktree is dirty (a dirty tree
means the thing you are about to test is not a commit).

## D1 — deploy parity (R-05)

```powershell
cd D:\NIDs_Windows
zig build
cargo build --release
cmake -B build; cmake --build build --config Release
cd nose; go build -o aegis-nose.exe .; cd ..

$repoExe = "D:\NIDs_Windows\zig-out\bin\aegis_nids.exe"
$repoHash = (Get-FileHash $repoExe -Algorithm SHA256).Hash

powershell -ExecutionPolicy Bypass -File scripts\install_aegis.ps1 `
    -BundleRoot "D:\NIDs_Windows\zig-out"

$installed = "C:\Program Files\AEGIS NIDS\runtime\aegis_nids.exe"
$instHash  = (Get-FileHash $installed -Algorithm SHA256).Hash
"{0}  repo"      -f $repoHash
"{0}  installed" -f $instHash
if ($repoHash -ne $instHash) { Write-Error "DEPLOY PARITY FAILED" }
```

**Pass:** the two hashes are equal and both are recorded in the transcript.
**Abort:** hashes differ after a second install attempt — do not proceed to D2
on an image you cannot identify.

## D2 — driver load and the absence of a block filter (R-06)

```powershell
powershell -ExecutionPolicy Bypass -File scripts\wfp_service.ps1 status
powershell -ExecutionPolicy Bypass -File scripts\wfp_service.ps1 install `
    -SysPath "C:\Program Files\AEGIS NIDS\drivers\aegis_wfp.sys"
powershell -ExecutionPolicy Bypass -File scripts\wfp_service.ps1 start
powershell -ExecutionPolicy Bypass -File scripts\wfp_service.ps1 status

powershell -ExecutionPolicy Bypass -File scripts\minifilter_service.ps1 status

# The detection-only claim, measured rather than asserted:
netsh wfp show state file="$env:TEMP\wfp_state.xml"
Select-String -Path "$env:TEMP\wfp_state.xml" -Pattern 'AEGIS' -AllMatches |
    Select-Object -First 20
```

**Pass:** both drivers report RUNNING and the WFP state dump contains **no
AEGIS-owned filter whose action is BLOCK**. AEGIS callouts may appear as
inspection/permit only.
**Abort:** bugcheck, loss of network, or a BLOCK filter with an AEGIS provider —
stop, roll back (section R), and file it as a stop-the-line finding.

## D3 — attributable loss measurement for #29 (R-07)

```powershell
# Attribution comes from the daemon's own counters, not from a total
python tools\aegisctl.py status
python tools\aegisctl.py metrics | Select-String 'queue_dropped|by_source_kind'
```

Run a burst that is attributable: a known fixture set pushed through the pipe
while the minifilter produces file events, for a fixed duration (10 minutes).

**Pass:** `queue_dropped` and the `by_source_kind` breakdown are recorded for
the window, and the decision (admission policy vs throughput) is made against
those numbers, not against the 52,823 figure from an older build.
**Abort:** counters move without an attributable source — the measurement is
then not usable and the decision must wait.

## D4 — heap crash attribution for #30 (R-08)

```powershell
gflags /p /enable aegis_nids.exe /full
for ($i = 1; $i -le 10; $i++) {
    Start-Service AegisNids; Start-Sleep -Seconds 20; Stop-Service AegisNids
}
gflags /p /disable aegis_nids.exe
# analyse the dump that WER wrote, then start the soak
Start-Service AegisNids
```

**Pass:** a stack signature names the faulting allocation/free, the fix targets
that signature, and a 24 h soak runs with the service still up.
**Abort:** no dump is produced — then the crash is not reproducible under Page
Heap and the honest status stays "unattributed", not "fixed".

## D5 — confirm B1 on the live service

```powershell
python tools\aegisctl.py enforcement.block --dst-ip 1 --dst-port 443 --protocol 6 `
    --policy-id 1 --event-id 1
# expect: failure_code DETECTION_ONLY, failure_state REFUSED

python tools\aegisctl.py enforcement.quarantine --dst-ip 1 --dst-port 445 `
    --protocol 6 --policy-id 1 --event-id 1
# expect: failure_code DETECTION_ONLY

netsh wfp show state file="$env:TEMP\wfp_state_after.xml"
Select-String -Path "$env:TEMP\wfp_state_after.xml" -Pattern 'AEGIS'
```

**Pass:** both verbs refuse with DETECTION_ONLY on the deployed binary, and the
filter enumeration is identical before and after the attempts.
**Abort:** either verb returns ENFORCED — that is a stop-the-line finding
against a build that was supposed to be detection-only.

## R — rollback (use it early, not as a last resort)

```powershell
powershell -ExecutionPolicy Bypass -File scripts\wfp_service.ps1 stop
powershell -ExecutionPolicy Bypass -File scripts\wfp_service.ps1 uninstall
powershell -ExecutionPolicy Bypass -File scripts\install_aegis.ps1 -Rollback
Get-Content "$backup\SHA256SUMS.txt"
Get-FileHash "C:\Program Files\AEGIS NIDS\runtime\aegis_nids.exe" -Algorithm SHA256
```

**Pass:** the restored binary hash equals the hash recorded in step 0.2 and both
services return to their pre-window state.
