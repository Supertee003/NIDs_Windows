## 3. Risk register

Each risk carries a detection signal, a mitigation, the slice that closes it,
and an exit criterion. **A risk with no closing slice is a planning defect, and
a risk with no exit criterion cannot be declared closed.** The mapping table in
section 3.3 is the completeness proof.

### 3.1 Severity and status vocabulary

- Severity: `S1` silent wrongness or data loss, `S2` blocked proof, `S3` drift
  or friction.
- Status: `OPEN`, `MITIGATED` (mechanism in place, proof pending), `CLOSED`
  (exit criterion met and recorded).

**Phase gate:** register current, Ring-1 debt 0, build truth 12/12, ratchet live,

### Phase B — close #25 (authority retirement, one patch, six layers)

1. Driver: `IOCTL_AEGIS_BLOCK_FLOW` returns `STATUS_NOT_SUPPORTED` before any
   state change; `UNBLOCK` stays cleanup-only for pre-existing filters.
2. Rust: `aegis_pep_enforce` classifies evidence and returns the assessment; it
   must not load or call the adapter; keep the symbol for ABI.
3. Zig control: hard-refuse `enforcement.block` / `enforcement.quarantine` with
   `DETECTION_ONLY` before any gate check.
4. Zig pipeline: `confirmed` is structurally false; projection is `observed`,
   `host_effect_confirmed=false`.
5. Rewrite T11 to the IDS contract with negative tests: no block filter can be
   installed or requested, and no receipt may claim a host effect.
6. Update ADR-0001 and every map; rebuild truth.

**Gate:** E1 (driver source + build) and E2 (Rust/Zig/tests). Host-level E5 for
this slice belongs to Phase D.

### Phase C — close #28 (ingestion payload/provenance)

Versioned frame binding (bounded payload + provenance) bound to the frozen
CanonicalEvent v1/v2, all six codecs, a shared `event_v*` vector, and Go-side
verdict removal — one patch. **Gate:** E2 + E3.

**Final product definition:** a detection-only kernel-telemetry NIDS for
Windows that (a) observes real network and kernel telemetry, (b) classifies,
correlates, records forensics and replays, (c) **structurally cannot** block or
mutate traffic, (d) installs, upgrades and rolls back, and (e) is signed and
reproducible — with every one of those claims proven at the level it is stated.

**Explicitly out of scope:** host enforcement, prevention, and any production
path emitting `host_effect_confirmed=true`. Re-entering this scope requires a
new decision gate and new evidence, not a code edit.

## 8. Review cadence

- After every slice: rebuild maps, update evidence index, confirm risk status.
- Weekly: recompute the debt numbers and the free-space figure; a risk whose
  numbers moved gets its status revisited.
- Before any release candidate: run the full checklist in FREEZE-001, then
  re-verify every row of section 6 and record the result in a closeout entry.

## Appendix — what this plan deliberately does not promise

1. No date estimates. A slice is done when its gate is met, not when a calendar
   says so.
2. No claim that the four stop-the-line issues are small. #25 and #28 are
   coordinated multi-layer changes; #29 and #30 need privileged host work.
3. No promise of E7. Without key custody the honest end state is a signed-less
   release with the limitation stated, and the definition of done records that
   as a declared exception rather than a pass.
