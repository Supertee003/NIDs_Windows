# NATIVE-BUILD-001 / OPS-PORTABLE-001 — a bridge that could not link, scripts for one machine

**Created:** 2026-11-14
**Build source:** `bridge/CMakeLists.txt` changed (native build tree), so this
slice moves the build source commit; `zig build` exits 0 and the truth maps are
restamped in the follow-up commit.
**Level:** E3 for the native adapters (real MSVC build of the shipped DLLs),
E2 for the script pins, E1 for the classification below.

---

## 1. What was found

1. **The bridge could not be built from a clean checkout.**
   `bridge/CMakeLists.txt` points every target at `<repo>/dist`, a gitignored
   directory that a clean tree does not have. Configure succeeded; the link then
   failed with
   `LINK : fatal error LNK1104: cannot open file 'D:\NIDs_Windows\dist\aegis_ipc.dll'`.
   MSBuild does not create output directories.
2. **The operator scripts pinned one machine.** `nose/run_nose.bat` and
   `nose/cleanup_nose_mouth.bat` hardcoded `D:\NIds_Windows\...` — a different
   case than the real path, and useless on any other host.
3. **A tracked script deletes tracked files.**
   `nose/cleanup_nose_mouth.bat` is a one-time v4→v5 migration that deletes
   `run_nose.bat`, `nose/README.md`, `mouth/Cargo.toml`, `mouth/Cargo.lock`,
   `mouth/.gitignore` and `mouth/src`. Run on a current checkout it removes
   files git tracks, with no prompt and no dry-run.
4. **The C stubs are orphans.** `src/tests/stubs/etw_helper_stub.c` and
   `fim_helper_stub.c` appear in no `CMakeLists.txt` and not in `build.zig` —
   nothing compiles them.

## 2. What changed

- `bridge/CMakeLists.txt`: `file(MAKE_DIRECTORY "${CMAKE_SOURCE_DIR}/../dist")`
  before the first target, so configure creates the output directory the linker
  needs.
- `nose/run_nose.bat`: `set "NOSE=%~dp0"` with trailing-slash trimming instead
  of an absolute drive path.
- `nose/cleanup_nose_mouth.bat`: an explicit gate —
  `if /i not "%~1"=="--run-cleanup" ... exit /b 2` — before any `del`/`rmdir`,
  a header stating exactly which tracked files it removes, and `%~dp0`-relative
  `NOSE`/`MOUTH`.
- `tests/release/test_native_build_and_scripts.py`, 9 pins:
  real MSVC builds of the three root DLLs (`aegis_wfp_user`, `aegis_etw_helper`,
  `aegis_fim_helper`) and of the bridge into `dist/aegis_ipc.dll`; the
  `file(MAKE_DIRECTORY)` line and its position before `add_library`; no drive
  path in the three batch scripts; the cleanup gate present and before the first
  delete, ending in `exit /b 2`; the stubs absent from both builds; the two
  `src/windows` C files still wired into the root build.

## 3. Verification

| Check | Result |
|---|---|
| `pytest -q tests/release/test_native_build_and_scripts.py` | 9 passed (twice) |
| root adapters, MSVC via the Visual Studio generator | 3 DLLs produced |
| bridge, MSVC | `dist/aegis_ipc.dll` produced |
| mutation: gate block removed from the cleanup script | 1 failed (`test_the_destructive_cleanup_script_stays_gated`) |
| restored | 9 passed |

**An observed environmental failure, recorded because it is instructive.** The
first two runs failed at link with `LNK1104` on `dist/aegis_ipc.dll` even though
the directory existed: a stale `dist/aegis_ipc.dll` from Sep 24 was in the way.
Moving that file aside let the link succeed, after which both runs passed. The
pin therefore also guards against a build tree that cannot be relinked — with
this message, which is what the operator needs to read.

## 4. Limitations

1. **E3 for the native adapters means "built and linked", not "loaded".** The
   three DLLs were not loaded by the runtime in this slice, and the bridge DLL
   was not exercised over its IPC.
2. **The Visual Studio generator is required.** The pins skip when cmake or a VS
   instance is missing, so a Linux/CI runner reports skips rather than proof.
3. **The gate is a guard, not a fix.** `cleanup_nose_mouth.bat` still deletes
   tracked files if someone passes `--run-cleanup`; it is a historical migration
   step, kept because deleting history is the owner's call, not this slice's.
4. **`drivers/` (6 files) and `rust-src/bin/aegis_keygen.rs` remain unbuilt.**
   The drivers need the WDK and a test-signing environment; the keygen is a
   standalone owner tool with no crate. They are classified in the accompanying
   evidence entry, which is a statement about what was *not* verified.
