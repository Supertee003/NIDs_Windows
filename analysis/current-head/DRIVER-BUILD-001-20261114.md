# DRIVER-BUILD-001 — both kernel drivers compile and link with the real WDK

**Created:** 2026-11-14
**Build source:** `tests/integration/` only — no `RUNTIME_PATHS` entry, soak unaffected.
**Level:** E3 (component: the shipped kernel binaries are produced).

---

## 1. From "parses" to "builds"

`DRIVER-SYNTAX-001` could only put the minifilter sources through `cl -Zs`,
because nothing in the repository built `drivers/`. It turns out the WDK is
installed on this host and both canonical build scripts work:

```
$ powershell -ExecutionPolicy Bypass -File scripts/wdk_build_production.ps1
[build] BUILD OK: D:\NIDs_Windows\build\x64\wfp\aegis_wfp.sys (41472 bytes)
[build] SHA-256:  2ECE7D52DEBFD45DC15FF381B659CE7391C4A4DF89B65746D8F4B5103988C71C

$ powershell -ExecutionPolicy Bypass -File scripts/wdk_build_minifilter.ps1
[build] BUILD OK: D:\NIDs_Windows\build\x64\minifilter\aegis_minifilter.sys (10240 bytes)
[build] SHA-256:  D011BB60F527FBBA53B4236AB40A3F7274D30269F3F89121D55AABB538D786AC
```

The minifilter build compiles four sources (`aegis_minifilter.c`, `_comm.c`,
`_file.c`, `_proc.c`) — including `aegis_minifilter_file.c`, which the debt census
never flagged because it was already named by an older entry.

The WFP build emits two `C4996` deprecation warnings for
`ExAllocatePoolWithTag` (WdM wants `ExAllocatePool2`, which the minifilter build
already uses). Warnings, not errors; recorded here rather than silently ignored.

## 2. What the gate asserts

`tests/integration/test_driver_build.py`:

1. `scripts/wdk_build_production.ps1` exits 0, prints `BUILD OK`, no `FAIL:`,
   produces `build/x64/wfp/aegis_wfp.sys` above a 16 KiB floor, and the printed
   SHA-256 matches the bytes on disk;
2. the same for `scripts/wdk_build_minifilter.ps1` →
   `build/x64/minifilter/aegis_minifilter.sys`, 4 KiB floor;
3. **no test in the suite invokes a driver signing, service or swap script** —
   those change kernel state, and the machine is running production drivers.

Both build tests skip when PowerShell or the WDK headers are absent.

## 4. Limitations — what an E3 driver build does not prove

1. **Compiling is not running.** These binaries were not signed, installed,
   loaded or unloaded. The drivers that *are* running on this host come from the
   install performed for the E5 gate, not from these freshly built binaries.
2. **No enforcement test.** Whether the WFP callout blocks a flow, whether the
   minifilter attaches to the right volume, and whether unload cleans up filters
   are all unverified. They need test signing, an elevated install and a lab
   network — and swapping drivers mid-soak would invalidate the window.
3. **No `.cat` catalog.** The INFs reference `aegis_wfp.cat` /
   `aegis_minifilter.cat`; signing is the owner's step
   (`wfp_sign.ps1`, `minifilter_sign.ps1`).
4. **Deprecation debt**: `ExAllocatePoolWithTag` in the WFP driver is a future
   compatibility risk on newer Windows builds.
