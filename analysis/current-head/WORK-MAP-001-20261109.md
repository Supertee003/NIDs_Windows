## Declarations (ambiguities resolved by evidence)

### config/ vs configs/ - which one is authoritative?

**Verdict:** configs/ is the live authority; config/Rules.json is a packaging mirror

**Proof:** SHA256 of both files is 87b97448e92eacba0534d65c929cf5f9599796b6c3d6a4eccd01cbd8269c4b74; tests/security/test_single_rule_authority.py fails if they diverge or if any code loads rules from config/; tools/aegisctl/api/control_api.py removed the fallback

### contracts/ vs shared/ vs tests/contracts/ - three contract locations?

**Verdict:** one authority, two consumers: shared/ is the contract authority, contracts/ is operator-facing reference, tests/contracts/ holds producer-owned vectors

**Proof:** git grep finds no runtime loader for contracts/; only README and analysis cite it

### lib/ - vendored UI assets with no visible consumer

**Verdict:** VENDORED, no authority; kept in place, must not be edited as project source

**Proof:** git grep for src="lib/ or href="lib/ returns no hit

### aegis_dashboard and shield look huge (1.53 GB, 125 files)

**Proof:** git ls-files aegis_dashboard -> Cargo.toml, Cargo.lock, src/main.rs

## Rules this map establishes

1. A unit with no status is a bug in the generator, not an oversight to explain.
2. Only `IN_PRODUCT` units may be claimed to ship.
3. `MIRROR` files are edited through their authority, never directly.
4. `DERIVED` and `LOCAL_ONLY` units carry no evidence obligation.
5. Moving a unit between statuses requires a new record, not an edit in place.
