## Patch result

OLD FLOW: The local WIP used mismatched pointer/slice parameters, silently broke out on null/wrap and could commit a partial batch without tracking overwrite count. Existing writer copied a whole extern header whose implicit padding was uninitialized, making authenticated bytes depend on stack contents.
NEW FLOW: Public batch records validated first -> one mutex -> shared `appendLocked` per record -> same writeSlot/hash/CRC/wrap/counter updates as single append. Header padding bytes are explicitly zeroed before hashing and CRC.
INVARIANT: For identical inputs, batch and repeated single appends produce byte-identical ring storage and identical count/head/tail/sequence/last hash/overwrites; rejected batch has no partial writes.
