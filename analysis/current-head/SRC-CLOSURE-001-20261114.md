# SRC-CLOSURE-001 — five modules said "never wire me in" and nobody checked

**Created:** 2026-11-14
**Build source:** `87e780e` unchanged in substance; this patch adds a comment
header to `src/reliability/reliability.zig` and a test, no logic change
(`zig build` exits 0)
**Level:** E2 (9 pins; the closure covers 293 tracked `.zig` files)

---

## 1. What was wrong

Five modules under `src/` open with a header stating their status — four say
`QUARANTINED ... must never be wired into the daemon`, `reliability.zig` is the
G20-G33 *specimen*, `federation.zig` says `SUPERSEDED, NOT the wiring target`.
`tests/security/test_forbidden_edges.py` already pins that production modules do
not import four of them, so the edges were guarded.

What was **not** guarded is the other half of the claim: nothing checked that
every `.zig` file is *reachable from a build root at all*, and nothing required
an unreachable file to say so in its own header. Measured at this HEAD:

- 293 tracked `.zig` files under `src/`, of which **285** are in the import
  closure of the eight `.zig` paths `build.zig` names (`src/main.zig`,
  `all_tests.zig`, `compile_only_imports.zig`, `out_of_unit_tests.zig`,
  `fuzz_entry.zig`, `tests/federation/federation_tcp.zig`, `perf_bench_main.zig`,
  `integration_test_main.zig`);
- the 8 outside it: the five above, plus `capture/npcap_test_live.zig` (a manual
  live-capture probe with no build target).

Two of the eight did not state their status anywhere a reader would find it:
`src/reliability/reliability.zig` opened with a G20-G32 changelog and no word
about being unwired, and `src/federation/federation.zig` says `SUPERSEDED`
rather than `QUARANTINED`. A 611-line file carrying a **second**
`ReliabilityWatchdog`, a stub `SecurityCheck` and drill-only canary/XDR types —
unbuilt, unmarked — is exactly the "duplicate authority" shape AGENTS.md lists as
a stop-the-line trigger. The `forbidden_edges` pin keeps it out of production,
but a reader opening the file had no way to know.

## 2. What changed

- `src/reliability/reliability.zig` now opens with the status its pin already
  assumes: SPECIMEN, NOT WIRED, which build roots do not reach it, which modules
  are the live homes of the same behaviour
  (`reliability/watchdog.zig`, `fault_injection.zig`, `security_check.zig`,
  `latency_histogram.zig`, wired in `daemon.zig`), and that its inline tests do
  not run under `zig build test`. Comments only: `zig build` exits 0.
- `tests/security/test_src_import_closure.py`:
  - the closure is computed from every `.zig` path `build.zig` names, so a new
    build target joins the check automatically;
  - `src/main.zig` must not reach any classified module (the whole-closure view
    of the property `test_forbidden_edges.py` pins edge by edge);
  - every tracked `.zig` must be reachable from some root **or** in the census,
    so a new orphan fails instead of accumulating;
  - the census may not go stale (a classified file that becomes reachable), and
    each classified file must use its status word in its own header;
  - a sanity floor: at least 250 modules must be reachable, so a broken
    `@import` parser cannot pass everything silently.

## 4. Limitations

1. **E2.** Reachability is a static `@import` walk, not a linker fact: a module
   reachable only through a `comptime` branch this walk sees as text still counts
   as reachable, and one behind a `@import` built from a variable would be missed
   (Zig requires `@import` arguments to be string literals, so this is a narrow
   gap).
2. **The closure starts where `build.zig` points.** A file that is meant to be
   built but whose root is added by a script outside `build.zig` would appear as
   an orphan — which is the intended failure, but it names the file, not the
   script.
3. **This does not re-prove the forbidden-edge property.** `test_forbidden_edges.py`
   owns it; this test only adds whole-closure reachability and the header census.
4. **`npcap_test_live.zig` is classified `TOOL_ONLY`, not removed.** It is a
   manual probe with no target; whether it should get one or be deleted is an
   owner decision.
