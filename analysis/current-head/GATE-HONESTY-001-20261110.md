## 1. Soak verdict (S1-05)

**Before.** `tools/host_soak_check.py` read only `status`, whose payload carries
no degraded flag, and its pass criteria were "four services RUNNING, daemon
reachable, uptime ≥ elapsed". It never looked at `health`, never counted loss,
and never looked for SCM restarts. A conceptual run over today's host —
`health.state = DEGRADED`, `queue_dropped_total = 265,675`,
`minifilter_pipeline_dropped = 1,016` — produced **PASS**.

**After.** The verdict fails closed on all of:

* required services not `RUNNING`,
* daemon unreachable, or uptime shorter than the window,
* `health.state = DEGRADED` / `degraded: true`,
* any of `queue_dropped_total`, `nose_frames_rejected`, `nose_frames_dropped`,
  `nose_pipe_errors`, `minifilter_ring_dropped`, `minifilter_pipeline_dropped`
  above `--loss-budget` (default 0, owner-approvable),
* SCM `7031`/`7034` for `AegisNids` inside the window.

The evaluation is a pure function (`evaluate()`), so the verdict is unit-tested
rather than trusted.

**Live result today** (exit 3):

```
"verdict": "FAIL",
"daemon_health_state": "DEGRADED",
"data_integrity": {"queue_dropped_total": 265675, "minifilter_pipeline_dropped": 1016, ...},
"problems": [
  "daemon reports DEGRADED (state=DEGRADED, runtime_state=RUNNING)",
  "queue_dropped_total=265675 exceeds the loss budget 0",
  "minifilter_pipeline_dropped=1016 exceeds the loss budget 0"

```

This is the correct answer: the run that was in progress is not a clean soak.
A new 24 h window starts after the host deployment (driver + helper + daemon).

## 2. Release digest gate (S1-02)

**Before.** `--refresh-digests` re-hashed the working tree and then called
`verify_manifest()` on that same tree, so any modified artifact was "verified"
by the act of refreshing it. The guidance in `FREEZE-001` item 9 was therefore
self-satisfying, and `--verify` was already failing today on
`scripts/package_release.ps1` — which a refresh would have erased.

**After.** `refresh_digests()` refuses to run while a **tracked** artifact has
uncommitted changes, and prints the blocking paths. Untracked build outputs stay
allowed (they are gitignored by design and have no HEAD blob to compare).

The workflow becomes: commit the source change → run `--refresh-digests` on a
clean tree → commit the manifest as its own records commit. That is already the
project's established shape (`test(truth): refresh release artifact digests …`).

**Binary coverage — corrected claim.** The survey said the gate covers no
binaries. It is true of `build_manifest.json` (651 entries, zero `.exe/.dll/.sys`),
but bundle-level coverage exists and was missed: `tools/release_candidate.py`
writes `SHA256SUMS` over every shipped file (`:143-148`) and verifies it
(`:213`). The honest gap is narrower than recorded: the *manifest* is
source-only by design, and shipped-binary digests live in the bundle manifest.
What was genuinely missing is that nothing compared the **installed** binary with
the **bundled** one — the same gap that let `aegis_fim_helper.dll` stay at the
2026-10-16 build (see `ISSUE-30-ATTRIBUTION-20261110.md`). The installer now
byte-compares each driver after copy and aborts on mismatch.

**Verification (live):**

```
python tools\release_engineering.py --refresh-digests   → exit 1, lists 5 dirty artifacts
python tools\release_engineering.py --verify            → exit 1, lists the real drift
tests/security/test_digest_gate.py                      → 2 passed
```

## 3. Evidence index (S1-03)

**Before.** `scripts/check_summary.py` counted `level` across `evidence` **and**
`known_gaps`, publishing `E5_count: 166` when the evidence section holds 77 —
the other 89 are open findings. `tools/evidence_debt.py` has always used the
opposite (correct) rule. 50 of 77 E5 entries had no artifact pointer, and four
entries asserted `host_effect_confirmed: true` with no scope marker on a
detection-only product.

**After.**

| Change | Effect |
|---|---|
| summary derived from `evidence` only | `E5_count: 77`, plus `E5_with_artifact_count: 27`, `known_gaps_count: 271` |
| `artifact_status: unrecorded` on E5 entries with no pointer | 50 entries now say so instead of implying an artifact |
| `scope: lab` + `historical: true` on the four host-effect entries | no unmarked host-effect claim survives |
| E5 ⇒ artifact pointer resolves (or an explicit status marker) | `check_summary.py` fails otherwise |
| one broken pointer corrected | `QLOSS-ISOLATION-002-E5-20261108` pointed at `…_114516-summary.json` (a file mtime); the run stamp is `…_114326-summary.json`, which exists |

Enforcement lives in three places, all passing:
`scripts/check_summary.py` (exit 0, `SUMMARY_VALID`),
`tests/release/test_evidence_index_valid.py`,
`tests/security/test_evidence_index_integrity.py` (two new tests: lab/historical
marker, E5 artifact disclosure).

The `head_sha` debt (35 of 74 distinct evidence commits do not resolve in this
repository) is **not** fixed here — it cannot be fixed retroactively without
rewriting history. It is now visible in this record and remains open.
